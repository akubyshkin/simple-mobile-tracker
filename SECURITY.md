# Безопасность TraceDay — аудит

Дата аудита: 2026-10-29. Объём: весь код `app/src/main`, манифест, gradle-конфигурация, история коммитов.

## Модель угроз

| Атакующий | Поверхность | Оценка |
|---|---|---|
| Вредоносное приложение на устройстве | exported-deeplink, общие каталоги | есть находки (С-1) |
| Физический доступ к устройству | ФС `/data/data/app.traceday` | частично защищено (С-3) |
| MITM в сети | весь сетевой трафик | защищено (TLS) |
| Облачный провайдер | файлы треков | данные публичны только по ссылке (С-4) |
| Утечка исходников | репозиторий | секретов нет |

## Что сделано правильно

- **Токены Яндекса** (access + refresh) хранятся только в `EncryptedSharedPreferences` (AES-256-GCM ключи, AES-256-SIV значения), в приватном каталоге приложения
- **Токены Google на диске не хранятся вовсе**: только имя аккаунта; OAuth-токены выдаются `GoogleAuthUtil` и кэшируются только в памяти (`cachedToken`)
- **Минимальные scope**: `drive.file` (только файлы, созданные приложением) и `cloud_api_3.disk`
- Весь трафик — HTTPS; `targetSdk 34` → cleartext-трафик запрещён по умолчанию
- **Никакого логирования**: в коде нет `android.util.Log`/`println`; `HttpLoggingInterceptor` не подключён — токены и координаты не попадают в logcat
- `allowBackup="false"` — БД и токены не уедут в облачную копию Android
- БД — параметризованные запросы Room (SQL-инъекций нет), лимиты импорта (20 МБ / 50 000 точек, битые строки пропускаются) — DoS через чужой файл исключён
- `TrackingService` не exported; `BOOT_COMPLETED` — protected broadcast (отправить может только система)
- WebView не используется — вход в Яндекс OAuth через Chrome Custom Tabs (изолированы от приложения)
- `local.properties` (ключи) в `.gitignore`; в истории коммитов секретов нет — `yandex.clientId` публичный идентификатор, не секрет
- Уведомление записи не содержит координат; токены в URL не передаются (код/refresh уходят POST-телом)

## Находки

### С-1 (СРЕДНЯЯ). Инъекция OAuth-кода через deeplink, тихое переключение облака — ИСПРАВЛЕНО

`MainActivity` — exported, intent-filter `traceday://oauth2`. Любое приложение может отправить `Intent(VIEW, traceday://oauth2?code=<код атакующего>)`. Код валиден (атакант сам проходит OAuth нашего client_id для **своего** аккаунта Яндекса), приложение молча обменивает его и переключает провайдера (`setCloud(YANDEX)`) — дальнейшие треки пользователя **синхронизируются на Диск атакующего**.

Исправление (вместе с тестами `YandexAuthStateTest`):
- вход инициируется только тапом «Подключить» — `YandexAuthManager.beginAuthSession()` генерирует криптослучайный `state` (SecureRandom, 16 байт) и запоминает его с TTL 10 минут
- `handleRedirect` принимает код только при активной сессии входа, сверяет `state` (последовательное несовпадение/отсутствие/истёкшая сессия → отказ), `state` одноразовый — расходуется при любой попытке
- код обмена `exchangeCode` стал приватным; через `CloudRepository` наружу торчит только `beginYandexAuth()`

### С-2 (СРЕДНЯЯ). Тихий fallback на незашифрованный файл токенов — ИСПРАВЛЕНО

`TokenStore.create()` при сбое `EncryptedSharedPreferences` молча писал токены в обычный `SharedPreferences` (`traceday_tokens.fallback`, plaintext).

Исправление: fail-closed — fallback удалён. Если зашифрованное хранилище недоступно (повреждение keystore), токены живут только в памяти процесса и на диск не пишутся вовсе; после перезапуска потребуется повторный вход. Plaintext-хранилища в приложении больше нет.

### С-3 (НИЗКАЯ). История перемещений в незашифрованной Room-БД — ПРИНЯТО РЕШЕНИЕ: не исправляем

`traceday.db` содержит до 7 дней координат (чувствительные данные). Смягчения: приватный каталог, FBE на современных устройствах, `allowBackup=false`, retention 7 дней.

Решение: дополнительное шифрование БД (SQLCipher) **не внедряем**. Обоснование:

- Android 10+ по умолчанию шифрует файлы аппаратно-привязанными ключами (FBE) — сценарий «вынули накопитель / сняли копию раздела» уже закрыт на уровне ОС; остаточный сценарий атаки требует root или форензики на разблокированном устройстве — вне модели угроз личного трекера
- Цена внедрения выше выгоды: +зависимость ~2 МБ (обедняет достигутое R8-сжатие APK), накладные расходы на каждый запрос, а главное — парольная фраза БД обязана где-то храниться (Keystore/EncryptedSharedPreferences) и превращается в единую точку отказа: сбой keystore = безвозвратная потеря всей истории (мы уже сталкивались с нестабильностью keystore в С-2)
- Ценность данных для атакующего ограничена retention'ом 7 дней и отсутствием копий вне устройства/облака пользователя
- Публичных данных это не касается: в облако уходит только то, что пользователь сам опубликовал ссылкой

Точка пересмотра: корпоративное использование, расширение retention или появление требований regulatorики к геоданным — тогда SQLCipher через `SupportFactory(passphrase)` без изменения схемы Room.

### С-4 (НИЗКАЯ). Нет отзыва публикации трека

«Поделиться днём» выдаёт файлу доступ «любой со ссылкой — читатель» **навсегда**; отменить публикацию из приложения нельзя. Ссылка угадываема слабо (длинный ID), но отозвать её нельзя. Рекомендация: кнопка «Закрыть доступ» (Drive: `DELETE files/{id}/permissions/anyone`; Диск: `PUT /v1/disk/resources/unpublish`).

### С-5 (НИЗКАЯ). R8/minify выключен — ИСПРАВЛЕНО

`isMinifyEnabled = false` в release — проще реверс-инжиниринг логики. В коде нет зашитых секретов, поэтому риск низкий.

Исправление: release-сборка по умолчанию проходит R8 (minify + obfuscation + shrinkResources; 22 МБ → 2.6 МБ), правила в `app/proguard-rules.pro`. Отключается флагом `./gradlew assembleRelease -Ptraceday.minify=false`.

### И-1..И-3 (информационные)

- `security-crypto` — alpha-канал (`1.1.0-alpha06`): следить за обновлениями
- Нет certificate pinning (стандартный компромисс; опционально для googleapis/cloud-api.yandex.net)
- Кэш тайлов osmdroid лежит в app-specific каталоге — содержит только публичные тайлы OSM (не чувствительно); координаты не валидируются по диапазону при импорте (влияет на отрисовку, не на безопасность)
